## P3 第四批：按语言分片扫描（方案 A）

- **前提澄清**：`run_rules` 早已按 `rule.language == parsed.language` 过滤；官方包 50 规则是 6 语言混合（JS/Python/Java/JSON 各 10，TS/TSX 各 5），每文件最多跑 10 条。之前"120 × 100KB JS 5分38秒 / 50 规则 × 45ms"是人为把 50 条全设成 JS 的压力测试。按语言分片**打不到"规则×大树"瓶颈**，只优化多语言 grammar 冷启动。
- **实现**：`scripts/scan_by_lang.py`（主）+ `scan_by_lang.sh`（便携回退）+ `merge_reports.py` + `check_sharded.py`。`--lang` 已存在，所以零核心代码改动；每个进程只构造自己语言的 grammar，stdout 出 JSON 由 merger 拼回。
- **合并正确性**（三处坑）：
  1. 跨语言文件在 N-1 个分片里被标 `unregistered-language`，真正未注册文件在全部 N 个 → merger 按出现次数过滤；ignored 在全部 N 个 → 保留。
  2. findings/warnings 用 **lexical_compare**（path,line,col,rule_id,fingerprint），但 `skipped.sort_by_key` 用 stdlib **shortlex**（长度优先，UTF-16 code unit）——见 `discover.mbt` 注释。用 `(len(utf16), s)` 排序。
  3. CLI 写报告附加裸 `\n`；Python 必须用 `write_bytes`（`write_text` 在 Windows 会变 CRLF）。
- **实测**：150 文件 6 语言冷扫描，单进程 1.576s、分片 1.108s，**端到端 1.42×**。分解：6 个 scan 并行 0.595s（纯扫描 2.65×），Python 解释器启动 0.327s 是固定开销。grammar 冷启动 1.33s → 0.23s/进程。单语言语料 0 收益。
- **Windows/Git Bash 性能坑**：每次 `echo | tr` 约 0.43s、6 次 `mkdir -p` 约 1.08s、`mkdir+rm` 6 目录约 2.97s。bash 版脚本因此从理论 0.6s 膨胀到 3.4s（比单进程还慢）；Python 编排规避 fork 开销。用 bash 参数展开 `${lang//[[:space:]]/}` 代替 `echo|tr`，分片输出写扁平目录/stdout。
- **验收**：verify 11 步全绿（新增第 11 步 `check_sharded.py`：py off/report/strict + sh off 四种组合全部 byte-identical），golden 100%/0%，cram 20/20，覆盖率 90.9%。

### 结论
按语言分片是低成本、低收益的正确性安全优化（不动核心代码）。真要解决大文件首轮慢，仍需 node-kind 规则裁剪；合并 Query 已证伪，不要重试。

## 官方 taint.json 补 source：strict 不再误删 positive

- **问题**：`--taint strict` 下 50 条 positive 被剔除 17 条。根因是 taint.json 的 source 只声明了真实 HTTP 输入（`req.query`/`request.args`/`getParameter`...），而 golden fixture 用的是语义化占位变量名（`userInput`/`payload`/`user_input`/`cmd`/`uid`/`id`/`input`），NoSource → 被 strict 剔除。这是 manifest 与 fixture 口径不一致，不是引擎 bug。
- **修法**：在每个语言的 sources 里补 identifier-source（`var_user_input`/`var_payload`/`var_uid`/`var_input` 等），按 sink_arg 的 identifiers 相交来配；TS007 的 sink_arg 是 `"javascript:alert(1)"` 字符串，补 `node_kind:"string", text_contains:"javascript:"`；PY005 sink capture=`arg`=`shell=True`，query 已用 `value:(true)` 让 negative（`False`）根本不命中，所以补 `identifier/shell` 作 source 安全，不会引入 FP。
- **关键认知**：taint 的"变量名相交"近似要求 source 节点的 identifier token 出现在 sink 捕获文本里——补 source 前先看规则的 query capture 与 predicate，不能照变量名直觉乱加。PY005 试过 `cmd`（在 sink_arg 之外）无效。
- **同步**：改 taint.json 必须跑 `gen_rulepack.py` 重算 manifest.json 的 taint_sha256，否则 rules-validate 报 SHA mismatch。
- **回归钉子**：`check_sharded.py` 新增断言——off 的 finding 路径集合 ⊆ strict 的，确保将来 source 被改坏时不再静默通过（原来只比三模式互相 byte-identical）。
- 验收：verify 11 步全绿，golden 100%/0%、cram 20/20、strict 从 33→50 条、off/strict 逐条一致。
