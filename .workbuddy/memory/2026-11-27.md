
## P4 spike 首批 10 条 MoonBit 规则验证：10/10 PASS

- **产物**：`p0-spike/moonbit-grammar/rules_moonbit.json`（MB001–MB010）、`rules_samples.json`（正反例+期望命中数）、`taint_moonbit.json`、`rules_check/main.mbt`（验证程序）。
- **验证方式**：`rules_check` 读两份 JSON，用与 `libs/query-engine/engine.mbt` 相同的匹配+谓词语义（8 种谓词全实现），对每条规则跑正例/反例，断言命中数 = 期望值。10/10 通过。
- **10 条规则**：MB001 process.run 命令注入(78)、MB002 fs.read_file 路径穿越(22)、MB003 硬编码 key(798)、MB004 crypto.md5(328)、MB005 Rand::new 弱随机(338)、MB006 Tls verify=false(295)、MB007 env 值写日志(532)、MB008 extern "C" FFI(1116)、MB009 HMAC digest=MD5(327)、MB010 空 catch(390)。
- **反例设计原则**：必须靠谓词区分而非靠 API 不存在——例如 MB001 反例是 `process.run("ls",...)` 靠 `not_has_prefix '"'`，MB006 反例是 `verify=true`，MB010 反例是 catch 内有 case_clause（原生 `#not-match?` 已由 probe 验证）。
- **踩坑**：MB006 初版把 TLS client 当模板 A 的 apply_expression，正例 0 命中——`@tls.Tls::client` 实际是 method_expression（同 MB005 模板 B），改 query 后通过。这印证了"先 dump AST 再写 query"的必要性。
- **schema 核对**：规则 JSON 字段集合、severity 取值、谓词 kind 与官方 `rules.json` 逐字段一致；taint sink 的 rule_id 全部有效。未做 rules-validate（其 query 校验依赖语言注册，moonbit 尚未并入主 registry）。
- **边界**：这是 spike 内验证，未并入主 workspace、未进 golden/verify。产品化仍需：registry 注册 moonbit + 绑定并入、fixture/golden 扩展、规则包发布。
- 复现：`cd p0-spike/moonbit-grammar && moon run --target native rules_check` → `RULES TOTAL=10 PASS=10 FAIL=0`。
