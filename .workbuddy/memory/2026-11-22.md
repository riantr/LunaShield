### 四项实测结论（重要，避免重复调研）
1. **T2 Windows native：Go**。`moon build --target native` 的 debug 与 release 均成功产出并运行 `.exe`，自动定位 MSVC（无需手工从 MSVC 终端启动）。`MOONBIT_NEW_NATIVE=1` 在本平台无差异，产物同为 172K。原"nightly 需回退"假设作废。
2. **T3 Query 谓词：Go（带兼容条件）**。`moonbit-community/treesitter@0.1.1` 完整实现 `#eq?`/`#match?`/`#any-of?` 及 not- 变体，`QueryCursor::matches` 通过 `TextProvider` 在匹配阶段执行判定；4/4 谓词过滤测试通过。
   - **关键坑**：`treesitter@0.1.0` + `moonc v0.10.21` 编译失败（0.10 起 impl 方法不自动提升为方法调用：`Position.compare`、`ErrorKind.to_string`）；必须 0.1.1+。
   - **仍未解决**：grammar 模块 `tree-sitter-json@0.24.8` 的 `binding.mbt:27` 仍有 `e.to_string()` 问题，需改为 `Show::to_string(e)`；官方无更新版本。已提为 T11。JavaScript/Python/Java grammar 是否同类问题未验证（T12）。
3. **T5 并发：Go，结论修正**。`moonbitlang/async@0.22.10` 有 `Semaphore`（acquire/release/try_acquire，README 明确支持 Bounded Concurrency）、`Mutex`、`cond_var`、`aqueue`。官方声明：**单线程协作式多任务**，内部 IO 用 OS 线程但用户不可见；无用户态线程。多核仍需多进程分片。并发限流直接用 Semaphore，不要自建 Mutex 计数器。
4. **T6 文件遍历：Go，结论修正**。`@fs.walk(path, async (String, Array[String])->Unit, exclude?, max_concurrency?, allow_failure?)` 内置。`walk` 源码语义（dir.mbt:604）：内部用 Semaphore 限并发 + TaskGroup 递归；回调 `(dir_path, entries)` 里 **entries 包含子目录名**，子目录会作为独立 dir_path 再次触发回调。扫描器只需按扩展名筛文件。实测 2/2 通过。

### 写 MoonBit 测试代码的注意点（踩过的坑）
- `async fn` 调用是隐式 await，lambda 要用 `<|` + 普通闭包（`group.spawn_bg() <| () => { ... }`），不要写 `async () => {}`。
- async 测试用 `async test "name" { ... }`。
- `set_language` 签名是 `-> Unit raise LanguageError`，用 `catch` 不是 `guard ... else`。
- `debug_inspect(content=...)` 的 content 格式与 `inspect` 不同（数组元素会被当 Char），简单断言用 `assert_true` 更稳。
- `moon new <dir>` 无 `--force`；Windows 上符号链接创建会回退为复制。

### T4 已关闭（同日补充实测）
- **core 内置哈希真相**：`core/builtin/hasher.mbt` 的 `Hasher` 是 **xxHash32**（GPRIME1..5），为 HashMap 的 Hash trait 设计，输出 Int32；默认 seed 在 native/JS 进程随机、Wasm 为 0，**稳定缓存键必须显式 `Hasher(seed=0)`**。core 无 SHA-256/FNV。
- **选用方案**：SHA-256 用 `mizchi/bit_hash@0.50.0`（one-shot `sha256_raw(Bytes)` + `Sha256State` 增量 + `hex_encode`；Apache-2.0；仅依赖 `mizchi/simd@0.6.1`）；gitignore 用 `mizchi/bit_ignore@0.50.0`（**零依赖**、Apache-2.0、gix 语义：`is_ignored(rel_path, is_dir)`、`add_rules(base, content)`、`truncate()` 回溯、否定/锚定/嵌套 base 全支持）。
- **踩坑**：`String::to_bytes()` 非 UTF-8 且已弃用，传给 sha256 得到错误摘要；必须用 `@encoding/utf8.encode(s)`。修正后 NIST 向量 "abc" → `ba7816bf...15ad` 正确。
- **被否决候选**：`Tigls/mb-hash@0.1.0` 仍是旧 `moon.mod.json` 格式，工具链拒绝安装；`gmlewis/sha256` 只有逐字节 API；`mooncrypt` 拉 3 个传递依赖。
- 实测：8/8 测试在 native/js/wasm-gc **三后端全通过**，工程 `p0-spike/t4-cache-ignore/`。报告 §7 与规划文档 A5/能力表/落地计划已同步，FNV-1a 自实现方案作废。

### 实测校准（重要，后续会踩）
- **`String::compare` 是 shortlex（先比长度再比码元）**，`"main.js".compare("binary.js") == -1`；路径排序必须用 `StringView::lexical_compare`。`source-file` 自带 `merge_sort_by` + `compare_strings`。

- 发现实现弃用 `@fs.walk`，改 `readdir`+显式 DFS：可按目录精确记录 `Unreadable`，且 walk 的 `allow_failure` 会吞错。

### 实测校准（M4）
- **`moonbitlang/core/strconv` 是空包**（mbti 无任何函数）→ 自写 `parse_uint(StringView)`；`Char::to_uint().reinterpret_as_int()` 是 ASCII 码，**必须 -48**。漏掉这步时 `--shard 0/1` 解析成 48/49，两个分片都扫 0 个文件（隐蔽 bug）。
- **相对路径不能直接做 IO**：discover 返回 root 相对路径，读文件要拼 root；否则 `root != "."` 时全 `unreadable`。集中在 `fs_path`。
- `@fs.write_file` 收 `String`（`impl Data for String`）；写报告文件要补 `\n`，否则 cram 报 `(no-eol)`。
- `@env.exit(Int32)` 是泛型 `fn[T] exit(...) -> T`，可在 `else` 分支当语句；`fail` 也写成 `fn[T] fail(msg) -> T` 以便在需要任意返回类型的 match 分支里用。
- 确定性：并发 push + 末尾统一排序 + `duration_ms` 恒 0；两次 `findings.json` `cmp` 相同。
- cram 再次确认：必须显式传目录；每块独立临时目录 → 规则包用 `printf '%s' '[...]' > rules.json` 内联。

### 实测校准（M5，都会再踩）
- **去重键必须是 `(path, fingerprint)`**：只按 fingerprint 去重会跨文件吞正例（negative.py 排序在前，positive.py 被丢掉），检出率假性下降 96%、反例假报 1 条。

- 谓词大小写敏感 → CFG fixture 用 snake_case 键（api_token/allowed_host/client_secret）。
- `object_creation_expression` 要带 `arguments: (argument_list . (_) @arg)` 才能区分字面量/变量；`new Random(seed)` 必须给正例传参。
- `String::compare` 是 shortlex（M2 已记），但本次又踩到"以为排序坏了"的同类陷阱——排序键语义先看文档。
