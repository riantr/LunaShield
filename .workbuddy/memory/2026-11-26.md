
## P4 spike 第 2 步：query 探针验证 capture 稳定性

- **目标**：产品化 MoonBit SAST 规则集前，先验证 tree-sitter Query 在自移植 grammar 上能否可靠命中（规则 query 依赖此假设）。
- **产物**：`p0-spike/moonbit-grammar/probe/main.mbt`（5 个探针用例）+ `QUERY_PATTERNS.md`（规则模板）+ 上游 `node-types.json`。
- **实测 5/5 PASS**：
  1. 无 named-field query 编译并命中（grammar 257 named 节点全部 fields 为空，不能写 `function:` / `arguments:` 字段锚点）。
  2. 位置锚点 `.` 必须显式写：`(arguments (argument) @arg)` 对每个参数都产生 match（2 参数=2 finding），`(arguments . (argument) @arg)` 只取第一个。
  3. capture 稳定：index 固定、重复运行逐字节一致。
  4. **capture 返回顺序 ≠ index 顺序**：`m.captures()` 按节点在树中位置返回，`@call` 覆盖整个表达式所以先返回，但 index 最大；engine 取最小 index 作 primary → primary 落在 `@pkg`。与现有 JS 规则 primary=callee 一致，可接受。
  5. **fn capture 带前导点**：`@fs.read_file()` 的 `@fn=".read_file"`、`@process.Process::new()` 的 `@ty=".Process"`、`@fn="new"`。谓词值必须照此写，否则规则永远不命中。
- **三组 query 模板**已固化在 QUERY_PATTERNS.md：A 包函数调用、B 类型构造函数、C 硬编码常量。
- **待补探针**（写规则前）：字符串插值 `\{expr}` 的污点、write_file 第 2 参数锚定、多行串密钥、空 catch。
- 复现：`cd p0-spike/moonbit-grammar && moon run --target native probe` → `PROBE TOTAL=5 PASS=5 FAIL=0`。

## P4 spike 第 2 步补探针：四项模式全部实测（11/11 PASS）

- 补齐首批规则依赖的四个 query 探针，并把 5 个扩到 11 个：`string_interpolation` 插值污点、`write_file` 第 2 参数锚定、多行串密钥、空 catch（含非空反例）。
- **实测修正了三个推断错误**：
  1. 文档原写 `(argument) _ . (argument) @arg` 会落空——实测**有效**，与 `(argument) . (argument) @arg` 都精确命中第 2 参数（1 match，arg=data）。
  2. 多行串 `multiline_string_content` 的文本**包含闭合符 `|#`**（`sk_live_1234567890|#`），规则只能用 `has_prefix`/`contains`，不能用 `text_equals`。
  3. 原生谓词必须写成 `((try_catch_clause) @catch (#not-match? @catch "=>"))`；若把 predicate 写在 pattern 外，会被解析成独立 pattern 匹配树上每个节点（实测空 catch 24 match、非空 36 match）。
- 空 catch 判定依据：`case_clause` 语法必含 `=>`，所以 `#not-match? "=>"` 等价于空 catch。
- 插值的 AST 是 `string_interpolation (interpolator (qualified_identifier ...))`，`@str` 为整段字面量、`@var` 为插值表达式。
- `QUERY_PATTERNS.md` 补四个模板 D/E/F/G，README 更新为 11 探针；spike 复现 `verify 31/31` + `probe 11/11` 全绿。
